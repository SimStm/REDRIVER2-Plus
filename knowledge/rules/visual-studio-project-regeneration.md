# Visual Studio project regeneration

`src_rebuild/build/*.vcxproj`, `src_rebuild/build/*.sln` and
`src_rebuild/dependencies/jpeg-9d/jpeg.vcxproj` are generated by
`src_rebuild/premake5.exe vs2022` (run from `src_rebuild`, with `SDL2_DIR`,
`OPENAL_DIR` and `JPEG_DIR` pointing at the `dependencies/...` folders). They are
git-ignored, so regeneration is invisible to `git status` while still changing
the user's build environment.

Two configurations exist **only** in those generated files:

- `Release_dev_gl` - the OpenGL variant referenced by `AGENTS.md` and the
  renderer documentation.
- `Release_dev_playground` - the playground variant.

The premake scripts define only `Debug`, `Release` and `Release_dev`, so
`premake5 ... vs2022` deletes both configurations from every project and leaves
the solution's configuration mappings pointing at projects that no longer have
them. A new source file under `src_rebuild/utils/` is also only compiled after
regeneration, because the generated projects list files explicitly even though
`premake5.lua` globs `utils/**`.

Therefore:

- Before regenerating, back up `src_rebuild/build` and
  `src_rebuild/dependencies/jpeg-9d/jpeg.vcxproj`; after regenerating, restore
  the hand-added configurations or re-add them.
- Re-adding means cloning every `Release_dev` block for both platforms -
  `ProjectConfiguration Include`, the `Configuration` `PropertyGroup`, the
  `ImportGroup` (its `Condition` comes **after** `Label`, so a
  `Tag Condition="` pattern misses it), the remaining `PropertyGroup` and the
  `ItemDefinitionGroup` - and substituting the configuration name inside each
  cloned block.
- Verify with `visual-studio-ide-mcp` `build_configuration_get`: the available
  list must still include `Release_dev_gl` and `Release_dev_playground` for
  both `Win32` and `x64` before building.
- Adding a source file to an existing generated project is a two-line edit
  (`ClCompile`/`ClInclude` in the `.vcxproj`, plus the matching entries in
  `.vcxproj.filters`) and is preferable to a regeneration when only the file
  list needs to change.

The OpenGL renderer does not need the `Release_dev_gl` configuration: it is
selected at runtime with the `-opengl` flag on `REDRIVER2_dev.exe`.
