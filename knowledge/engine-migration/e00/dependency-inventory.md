# E00 - Dependency inventory and behavioral baseline

First stage of [engine migration](../../roadmap/planned/engine-migration.md).
This record inventories every required PsyCross contract on `feat/new-engine`
and establishes the build/timing/replay facts the later stages depend on. It is
evidence, not a removal claim: nothing is removed here.

- Branch: `feat/new-engine` at `9c353405` plus this E00 work.
- PsyCross fork gitlink: `37d399dfd4584df746647cba4d2d832bc27f0922`, clean.
- Mechanical appendix: [symbol-usage.md](symbol-usage.md), [includes.md](includes.md),
  generated by [`scripts/engine_migration/e00_symbol_scan.py`](../../../scripts/engine_migration/e00_symbol_scan.py).

## Method

The scan parses the Psy-Q compatibility headers (`PsyCross/include/psx/*.h`)
and PsyX public headers (`PsyCross/include/PsyX/**`), extracts declared
functions/macros per category, and counts whole-token usages in game-owned
sources (`Game/`, `utils/`, `platform/`, `redriver2_psxpc.cpp`), excluding the
submodule. 3618 declared symbols; 400 used; 3218 declared-but-unused.
Generic C names (`read`, `open`, `cd`, `NULL`) appear in the appendix because
Psy-Q headers redeclare libc names; they are not service consumers.

Build/dependency facts were read from `premake5.lua`,
`premake5_psycross.lua`, `windows_dev_prepare.ps1` and the generated projects.

## Service inventory

### GTE and fixed-point math - project extraction (E01)

Consumers: 46 `gte_*` macro symbols (584 refs) plus 20 libgte functions
(172 refs). Heaviest: `debris.c`, `tile.c`, `cars.c`, `motion_c.c`, `draw.c`,
`shadow.c`, `handling.c`, `camera.c`, `sky.c`, `convert.c`. `rcossin_tbl`
backs `RSIN/RCOS/isin/icos` (`Game/dr2math.h:36`), `RAND` is an LCG
(`dr2math.h:42`), `ONE=4096` (`dr2math.h:24`). `getScratchAddr` (libetc macro,
33 refs) is the GTE scratch area contract.
Owner: `PsyCross/src/psx/LIBGTE.C` (interpreter-style C), `src/gte/PsyX_GTE.cpp`
(30 KB of `gte_*` helpers), `gte/rcossin_tbl.h`.
Classification: **project extraction**. The game relies on exact fixed-point
overflow/rounding and update ordering; preserve arithmetic before changing
owners. GTE is not rendering-only: handling/collision/camera use it.

### Clocks and vblank - modern adapter (E01)

Consumers: `VSync` 56 refs (`E3stuff.c` 15, `FEmain.c` 8, `glaunch.c` 6,
`main.c` 6), `SetVideoMode`, `GetVideoMode`, `VSyncCallback`,
`StopCallback`, `ResetCallback`; `sysclock.c` event/timer API.
Owner: `PsyX_main.cpp` - a dedicated SDL thread increments
`g_psxSysCounters[PsxCounter_VBLANK]` every `FIXED_TIME_STEP_NTSC/PAL`
(60/50 Hz, `PsyX_globals.h:11`); `VSync(-1)` reads the counter
(`PsyX_main.cpp:167`), `VSync(0)`/`PsyX_WaitForTimestep` busy-wait
(`PsyX_main.cpp:1240`), and `LIBETC.C:31` routes both. Game side:
`FilterFrameTime` (`main.c:1285`) requires 2 vblanks, so the desktop tick is
30 Hz NTSC / 25 Hz PAL; `State_GameLoop` (`main.c:1565`) steps once
(`FastForward ? 7 : 1`), then draws; PSX has an additional
`clock_realTime.time32Hz` catch-up path (`main.c:1586-1610`) that desktop
does not use. `glaunch.c:486` derives `gRandomChase = VSync(-1) % 13 + 2` from
the live counter - wall-clock enters gameplay.
Classification: **modern adapter** to a project clock/tick service. The tick
must stop reading the emulated vblank; initial cadence stays 30/25 Hz.

### Pad input - modern adapter (E01)

Consumers: `Game/C/pad.c` wraps `libpad` (`PadInitDirect`, `PadStartCom`,
`PadGetState`, `PadInfoMode`, `PadSetActAlign`, `PadSetAct`) and exposes
`Pads[2]` (`direct`, `dirnew`, `mapped`, `mapnew`, `mapanalog[4]`, vibration).
`ReadControllers` (`pad.c:419`) runs `PsyX_UpdateInput()` then maps raw bytes;
`UpdatePadData` (`system.c:702`) runs once per game tick and copies `Pads[0]`
into `paddp/padd`. Owner: `PsyCross/src/pad/PsyX_pad.cpp` (SDL2 controllers,
keyboard mapping), mapping globals in `PsyX_public.h`.
Classification: **modern adapter**; keep the `Pads[]` mapping contract and
per-tick sampling. Analog unpacking, disconnect (`pad_connected`) and vibration
are game-visible semantics.

### Audio (SPU/music/CD-XA) - modern adapter to FMOD (E04)

Consumers: `sound.c`, `xmplay.c` (28 libspu symbols, 33 SPU macros),
`gamesnd.c`, `mc_snd.c`, `glaunch.c`, `main.c`, `fmvplay.c`; `xaplay.c` for XA
music. Owner: `PsyCross/src/audio/PsyX_SPUAL.cpp` (OpenAL) and
`src/psx/LIBSPU.C`. The game allocates SPU voice memory (`SpuMalloc`,
`SpuInitMalloc`), programs voice attributes/ADSR/pitch/volume, reads key
status, and uses reverb modes.
Classification: **modern adapter** to FMOD Core behind a project audio
contract (E04); no FMOD calls inside gameplay systems.

### CD, streaming and filesystem - project extraction + adapter (E01)

Consumers: `system.c` (`Loadfile`, `FileExists`, `LoadfileSeg`, `loadsectors`,
`DiscSwapped`), `spool.c` (`CdControlF`, `CdGetSector`, `CdDiskReady`,
`DrawSyncCallback` x7, `LoadImage2`), `xaplay.c`, `fmvplay.c`, `E3stuff.c`,
`glaunch.c`, `main.c`. `loadsectors` (`system.c:575`) uses
`CdControlF(CdlReadS)` + `CdDataCallback`/`CdReadyCallback` and then spins on
`load_complete`; a `USE_PC_FILESYSTEM` path (`loadsectorsPC`, `utils/fs.*`)
reads the installed folder directly. `DrawSyncCallback` couples streaming to
the GPU draw sync.
Classification: **project extraction** for the stream/callback contract;
PC-filesystem and ISO paths both remain explicit. Do not hide expected
loading states.

### GPU, VRAM, offscreen and present - temporary compatibility consumer (E02/E03)

Consumers: `libgpu` 27 functions (276 refs) + 36 macros (561 refs):
`DrawSync` 84, `LoadImage` 40, `SetDispMask` 29, `DrawPrim` 29, `ClearOTagR`,
`ClearImage`, `GetClut`, `ResetGraph`, `DrawOTag`, `DrawSyncCallback`,
`GetTPage`, `LoadClut`, `FntPrint`, `StoreImage`, `SetDrawEnv`, plus
`addPrim`/`setPoly*`/`setXY*` primitive builders. Primary consumers:
`E3stuff.c`, `FEmain.c`, `overmap.c`, `loadview.c`, `pres.c`, `spool.c`,
`texture.c`, `system.c`, `draw.c`, `sky.c`, `cars.c`.
Owner: `PsyX_GPU.cpp` + `PsyX_render.cpp`/`PsyX_Vk.cpp` (VRAM model, OT
traversal, CLUT/tpage decoding, offscreen). `SetPsyXTexture`/`LoadImage2`/
`StoreImage2`/`ClearImage2` are PsyCross extensions used by `pres.c`,
`spool.c`, `FmMain.c`.
Classification: **temporary compatibility consumer**; E02/E03 replace the
game's draw commands with converted resources. VRAM semantics (`LoadImage`,
`StoreImage`, `MoveImage`, readback) stay required by texture conversion, HD
override registration and inspector export until their replacements land.

### Window, present and platform - project platform service (E01/E03)

`redriver2_psxpc.cpp` owns startup: `PsyX_SetRenderBackend` (Vulkan default,
`-opengl` selectable), `PsyX_Initialise`, `PsyX_CDFS_Init`, `PsyX_Shutdown`.
Developer paths use `PsyX_ApplyWindowMode`, `PsyX_GetSDLWindow`,
`PsyX_GetScreenSize`, `PsyX_SetCursorPosition/Relative`, swap-interval
controls (`main.c:828` sets interval 2 for 30 FPS).
Classification: **project platform service**. E03 must have one
device/swapchain/present owner; no simultaneous PsyCross and Diligent
swapchains on one window.

### ImGui, inspector and developer tools - temporary compatibility consumer (E05/E07)

`utils/DeveloperGraphicsPanel.cpp` (99 KB) + `DeveloperModernMesh.cpp` (35 KB)
+ `DeveloperVkFixture.cpp`, `HdTextureOverrides.cpp` (85 KB),
`DeveloperDebugStart`, `DeveloperInputMapping`, `DeveloperGraphicsSettings`.
They consume PsyX hooks: `PsyX_SetSDLEventHandler`,

`PsyX_Inspector_*` (pick/selection/export), `PsyX_ModernMesh_*` (experimental

Classification: **temporary compatibility consumer**; ImGui must be

### Diagnostics - modern adapter (E01)

`Game/driver2.h:59-62` maps `printInfo/Warning/Error` to `PsyX_Log_*`; `trap`
and `D_CHECK_ERROR` build on it. Replace with project logging that keeps
explicit failures (no silent legacy fallback).

### Unused declared surface - explicit, not removable yet

3218 declared symbols are unused by this branch's game sources, including all
of `libpress`, most `libsn`/`r3000`/`asm` helpers and most GTE register
accessors (the appendix lists them). Their presence in headers/tests still
belongs to the submodule; removal is E07, not E00.

## Regional, timing and arithmetic contracts

- `GAME_REGION` is `NTSC_VERSION` or `PAL_VERSION` (`premake5.lua:33`).
  `system.h:125-133`: screen height 240/256, `draw_mode_pal/ntsc`,
  `video_mode MODE_PAL/MODE_NTSC`; `system.c:817-823` aspect `m[1][1]`
  4300 PAL / 4096 NTSC. `CDSECTOR_SIZE` 2048 (`system.h:156`).
- Tick cadence: 2 vblanks per tick => 30 Hz NTSC, 25 Hz PAL. `FastForward`
  steps 7 simulation iterations per drawn frame (`main.c:1612`).
- Simulation index: `CameraCnt++` inside `StepSim` (`main.c:1164`); draw
  index: `FrameCnt++` at the end of `DrawGame` (`main.c:1674`). Gameplay reads
  both: `FrameCnt` in debris lamps/trails (`debris.c:1693,2251`), camera
  `viewChange` (`camera.c:132,224`), many `FrameCnt > 2` checks.
- `sysclock.c` implements the 128/64/32 Hz `Clock_tGameClock` from the
  timer-event API; `inittimer(120)` runs only on PSX (`main.c:819`).
- RNG: `srand(0x1234)` (`main.c:790`, `main.c:2535`) seeds the **libc** `rand`
  used throughout gameplay (`debris.c`, `cosmetic.c`, `director.c`,
  `bcollide.c`, `job_fx.c`, `event.c`, `handling.c`, ...). `RandomInit(0xd431,
  0x350b1)` adds a second generator (`main.c:2536`); `RAND()` is the LCG macro
  (`dr2math.h:42`); `Random2` derives values from `CameraCnt` (`convert.c:186`).
  Determinism across toolchains therefore requires pinning/replacing the libc
  `rand` sequence - a concrete E01 contract.

## Replay, cutscene and input-recording contracts

- `replays.c`: `REPLAY_IDENT` magic `'D2RP'`; `SaveReplayToBuffer`
  (`replays.c:110`) writes `REPLAY_SAVE_HEADER` (GameLevel, GameType,
  MissionNumber, streams, players, RandomChase, cop difficulty, cheats,
  wantedCar, mission-end data) then per-stream `REPLAY_STREAM_HEADER`
  (`SourceType`, byte size, `Length`) and run-length `PADRECORD`
  (`pad`, `analogue`, `run`). `Get`/`Put` (`replays.c:368,401`) expand repeats
  per `CameraCnt`; `cjpRecord`/`cjpPlay` (`replays.c:445,477`) are the per-tick
  input record/playback hooks used by `StepSim`. Analogue steering uses the
  16-entry `AnalogueUnpack` table. Attract replays load from
  `REPLAYS\ATTRACT.<mission>` (`replays.c:286`); chases/cutscenes live in
  `REPLAYS\*.R` with the `CUTSCENE_RECORDER` tooling.
- Old tapes are tick-repeat based. E01 must keep them readable (or diagnose
  version/region explicitly) and must not silently resample PAL tapes to 30 Hz.
- Input sampling happens once per tick: `UpdatePadData` -> `ReadControllers`;
  gameplay consumes `Pads[*].mapped/mapnew/mapanalog` and records via `cjp*`.

## Draw-time mutation and RNG sites

- Rendering runs after the tick in `DrawGame` -> `RenderGame2`; it increments
  `FrameCnt` (read by gameplay), swaps buffers, and mutates presentation-only
  state. `Havana3DOcclusion` (`main.c:2633`) rewrites `events.camera/draw` and
  the OT for the Havana interior. `DoWeather` is called from the draw path
  (`main.c:2466`) and mutates rain/wetness state; `DisplaySplashes`
  (`debris.c:3607`) and `AddRainDrops` (`debris.c:3796`) use function-local
  static LCGs, not the global gameplay RNG.
- Every global `rand()`/`RAND()` gameplay site found by the scan sits in a
  simulation function (`AddSmokingEngine`, `AddFlamingEngine`, `AddLeaf`,
  `CreateBirds`, `damage_object`, `Setup_Debris/Smoke/Sparks`, `DoLightning`,
  `DoThunder`, `DoAutoDirect`, `StepHelicopter`, `HandleExplosion`,
  `CarBuildingCollision`, ...). The known clock leak into gameplay is
  `gRandomChase = VSync(-1) % 13 + 2` (`glaunch.c:486`).
- Conclusion for E01: rendering currently does not consume the gameplay RNG,
  but it advances `FrameCnt` and presentation state that gameplay reads, and
  the vblank clock leaks into one gameplay value. Both must be decoupled.

## Baseline build and run evidence (2026-10-08)

- Isolated generation: `RED2_BUILD_DIR` / `RED2_BIN_DIR` with `premake5 vs2022`
  produced `src_rebuild/build_e00` (NTSC) and `build_e00_pal` (PAL) from this
  branch's sources and gitlink without touching the rework's `build/` outputs.
- Builds: MSBuild `Release_dev|x64` succeeded for both regions ->
  `bin/Release_dev/REDRIVER2_dev.exe` and `bin/pal/REDRIVER2_dev.exe`.
- Deterministic checkpoints: `utils/DeterministicBaseline.{h,cpp}` writes a
  field-wise canonical record once per simulation tick (`-statedump <file>`,
  optional `-statedumpevery N`), hashed with FNV-1a over explicit gameplay
  fields only (`FrameCnt` is diagnostic context, never hashed).
  `scripts/engine_migration/e00_compare_state.py` compares two dumps per tick.
- Executed results:
  - NTSC `-replay DRIVER2\REPLAYS\ATTRACT.400`, two runs: 714 shared ticks,
    **0 mismatches**.
  - PAL same replay, two runs: 595 shared ticks, **0 mismatches**.
  - NTSC vs PAL same replay: 597 shared ticks, **0 mismatches** - this old
    attract tape is region-invariant in simulation state on both builds.
  - NTSC `-mission 1`, two runs: 726 shared ticks, **0 mismatches**.
  - Each run was stopped by wall clock, so the trailing record count differs;
    all shared ticks matched.
  - NTSC smoke `-nointro -nofmv`: Vulkan rendered an in-game Chicago scene at
    ~29 FPS; `REDRIVER2.log` shows `AssetCatalog: level 0 ... 497 models, 303
    textures, 6 cars` plus modern-fixture imports.
- Old-format sample: `-replay DRIVER2\REPLAYS\CUT10.R` is rejected with
  "Error loading replay file" - `-replay` accepts only the `D2RP`
  `REPLAY_SAVE_HEADER` stream format (attract/replay tapes); `.R`
  cutscene/chase files are a distinct format consumed by the cutscene/director
  path, not by `LoadReplayFromBuffer`.
- Not yet captured: interactive driving/collision/police routes (need recorded
  input), pause/loading, an explicit region transition, replay re-record, and
  GPU captures/performance budgets. The state-dump hook is the fixture basis
  for those E01 runs.
